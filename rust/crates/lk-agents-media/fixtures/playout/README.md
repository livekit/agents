# Streaming PCM playout fixtures

The listening source is a 26.25-second mono 24 kHz PCM16 passage generated by OpenAI
GPTLive (`gpt-live-1`, voice `marin`). It discusses audio buffering and counts objects.
Only source leading/trailing silence was trimmed, retaining 20 ms of padding on either side.
Internal pauses remain. Output tracks retain all startup, underrun and recovery delay.

`source.json` records the requested passage, returned transcript and timestamps, observed
chunk lengths/arrival times, model, voice and source SHA-256. No customer audio or API
credentials are included. Audio is stored outside Git. Hermetic regression tests generate deterministic PCM in memory.
The metadata records the previous listening run; a fresh GPTLive capture need not match its hash.

## Generate the comparisons

From the repository root, with Cargo, FFmpeg and a C++20 compiler available:

```sh
python3 rust/crates/lk-agents-media/tools/compare_playout.py \
  --input /path/to/gptlive-speech.wav \
  --webrtc /path/to/mac-arm64-release \
  --output /tmp/playout-comparison
open /tmp/playout-comparison/index.html
```

`--webrtc` is an extracted distribution from the `webrtc-a545de4` release of
https://github.com/livekit/rust-sdks/releases/tag/webrtc-a545de4. The helper never downloads
anything or substitutes a mock for NetEq. It records the linked archive's SHA-256 in
`report.json`; callers using another build must review that provenance. The standalone
reference helper currently supports the macOS distribution and system-libc++ Linux builds.
It is not a product dependency.

The Rust example uses the production `playout::Playout`. All four branches receive the
same source samples and actual ordered arrival schedule. NetEq's L16 codec supports
8/16/32/48 kHz, so only that branch is resampled offline 24→48→24 kHz. Each transport chunk
is divided into <=20 ms L16 packets **with the exact same arrival time**. The comparison
is a behavioral/audio reference, not a claim of sample equality, equal achieved delay,
or equivalence to Opus decoder PLC. NetEq can keep concealing after source EOF; its total
concealment counter therefore includes the two-second trailing observation window.

The player includes original speech, untreated playback (no jitter buffer, abrupt silence
on starvation), a plain 100 ms FIFO buffer, actual libwebrtc NetEq, and the Rust controller. Each has its actual delay;
the Playback menu switches tracks at the same wall-clock position. The stereo WAVs provide wall-clock-aligned
baseline/NetEq on the left and candidate on the right. Use headphones or select one channel
in an audio editor. `timeline.csv` and `statistics.txt` describe the candidate's decisions.

Scenarios: clean 100 ms batching, 20 ms lateness, a 30 ms no-reserve underrun, repeated 40 ms stalls, ordered backlog
bursts, a permanent delivery delay increase, a one-second outage, changing 20–200 ms chunk
sizes, and 1000 ppm clock drift. Add `--scenario late_20ms` to render one case, and
`--delay-ms 0` to expose concealment without a startup reserve. The default 20 ms reserve
can absorb the isolated 20 ms delay without concealment. Sweep delay budgets explicitly;
these fixture defaults are not production recommendations.

## Recovery DSP

The controller accepts continuous ordered mono 24 kHz PCM16. Source-only noise analysis
runs at a fixed sample cadence, independent of incoming chunks and render call size.
A stabilized sixth-order LPC model generates unvoiced continuation using measured residual
energy. Multi-candidate correlation and distortion searches select alternating pitch periods;
a signal-dependent envelope preserves short voiced gaps and fades unstable transients. Speech fades into a
separately learned, conservative room-tone model. Long gaps eventually mute; silence does
not turn into a tone. No generated audio trains the background model.

Recovery validates two consecutive source windows for a phase match to the generated
continuation. A bounded continuation prefix aligns a strongly matched voiced return,
without skipping source samples or abruptly warping the waveform. It crossfades with
correlation-aware energy normalization and restores gain after a faded outage. Unvoiced onsets use a shorter merge than strongly correlated voiced returns.
Overlap/add time stretching validates a splice over two windows and handles quiet signals
without a pitch estimate. Unreliable transient matches are left untouched.

The implementation is independent Rust DSP, not a sample-exact NetEq port. Tests cover
pitch, unvoiced spectrum, room tone, phase inversions, long-gap gain recovery, full-scale
and DC inputs, repeated noisy underruns, EOF/reset, sample accounting and allocation bounds.
Human listening review and production integration remain outstanding; these tests do not
establish perceptual equivalence to NetEq. All accepted source audio is preserved, so long
outages can add delay beyond the adaptive target. Provider/runtime wiring and host exports
are outside this media-only change.

## Audible fault placement

The renderer measures 10 ms source RMS windows and refuses fixtures without a verified
active fault region. The primary fault starts where the first 50 ms exceeds 150 PCM RMS
and at least 70% of the next second is active. Repeated stalls are restricted to active
source windows. `report.json` records the selected onset, threshold and all window RMS
values. Run `python3 -m unittest discover -s rust/crates/lk-agents-media/tools -p
'test_compare_playout.py'` from the repository root for placement regressions. These
energy checks establish audibility, not semantic intelligibility or a perceptual score.

The no-reserve listening case uses a 30 ms delay; input chunk duration remains 100 ms.
Playback-added delays are retained.

Fault placement prefers two seconds (`--fault-at-ms 2000`) and selects the nearest
verified active window. For this passage that is 2.2 seconds; 2.0 seconds fails the activity check.
All stall cases, chunk-size changes and clock drift begin at that common source time.
The clean row has no injected fault and is a comparison reference.

## Sustained slow delivery

`slow_jittery` begins at the common speech-active onset. It uses deterministic correlated
queueing variation, active-speech stalls, ordered catch-up bursts and a sustained 2% source
clock shortfall. It is a synthetic stress case, not a measured provider trace. The original
fixed 40 ms delay case can underrun once and then retain that much reserve; repeated delay
injection alone does not establish repeated audible underruns. Compare achieved latency,
gap duration and listening quality, not just the injected delay count.

## Focused listening cases

The PR table retains Startup, Jitter, Burst, Outage and Catchup. Other scenarios remain available
in the offline tool.
`startup_jitter` delays source chunks 1–4 by 60, 100,
160 and 300 ms. Ordered arrivals for chunks 0–7 are 0, 160, 300, 460, 700, 700, 700,
700 ms. Speech is active at the first underrun (100 ms), so this tests the beginning
of an answer before much history or buffering has accumulated.

`reported_jitter` uses 20–90 ms delivery variation with occasional 300 ms delays restricted
to active source speech. It reflects the reported symptom that a 100 ms reply buffer
absorbs many gaps but cannot absorb a 300 ms delivery stall. The magnitudes are inspired
by the report; the schedule is synthetic because no packet-arrival trace was supplied.
No customer recordings or Slack message content are included in these audio artifacts.

## Delay decisions and attribution

A fixed-size, source-time arrival envelope distinguishes transport batching from jitter.
A Q30 delay histogram samples 500 ms peaks and selects the 95th percentile. The acceleration
threshold includes the recent arrival envelope, avoiding immediate removal of reserve just
refilled by a late chunk. After heavily faded concealment, recovery waits for half the target
reserve unless the stream has finished. The default speech extrapolation ceiling is 200 ms;
this is a ceiling, not a fixed fade or additional startup delay.

Histogram arithmetic and expand-analysis formulas are adapted from WebRTC NetEq at
`a545de4` (`histogram.cc`, `expand.cc`); the BSD license and patent grant are included as
`LICENSE.webrtc` and `PATENTS.webrtc`. The implementation uses floating-point 24 kHz PCM
analysis rather than reproducing NetEq fixed-point processing.

## Time scaling and catch-up

The Q8 timing filter updates on a 10 ms rendered-sample cadence and compensates successful
stretching immediately. Timing comparisons retain sample precision, including fractional
milliseconds. Ordinary operations are at least 50 ms apart and share the configured rate
budget. History-assisted preemptive expansion also works with only 20 ms of new audio;
new onsets must pass independent history/source correlation and amplitude checks.
Passive speech detection uses eight times the conservatively learned room-tone energy.

Severe backlog (four times the upper decision threshold) permits fast acceleration:
verified pitch multiples, a 0.5 correlation threshold rather than the ordinary 0.9, and
bypassing the ordinary cooldown. It still respects the same insertion/removal budget.
It does not silently discard a chunk or promise immediate recovery of arbitrarily large delay.

`catchup` starts at the common active-speech onset. A provider sends 1.5 seconds of source
in 0.5 seconds (3x realtime), creating one second of additional queued speech, then resumes
realtime delivery. No render pause, packet loss or reordering is fabricated. The renderer
records each actual acceleration event, its removed duration, and whether fast mode was
used in `report.json`; `timeline.csv` has cumulative normal/fast totals and merge prefixes.
These are measured operation times, distinct from the schedule onset in the PR labels.

See [NetEq coverage](neteq-coverage.md) for the complete operation/stage inventory,
regression evidence and explicit transport/decoder exclusions.

## Sustained listening comparison

The PR Jitter row uses `sustained_jitter`: 20 seconds of 1% slower source delivery plus
0–30 ms variation on verified active-speech chunks, starting near 2 s. After that period,
delivery resumes at realtime with the accumulated 200 ms delay retained. No source is
lost, reordered or discarded; the untreated FIFO is never reset to manufacture gaps.

Bounded jitter alone eventually gives an untreated FIFO enough retained delay to stop
underrunning. This case explicitly includes a rate deficit to exercise recurring gaps
throughout the passage. It evaluates ongoing concealment; the current Rust controller
still underruns in this case and is not demonstrated to provide gap-free buffering.
The original 20–90 ms / 300 ms `reported_jitter` case remains available separately.

`fifo_timeline.csv` records actual untreated consumption/starvation on every render.
`report.json` lists each gap's onset, duration and source-energy check, so the continued
faults can be verified rather than inferred from injected packet delays alone.
