# Streaming PCM playout fixtures

The listening source is a 26.25-second mono 24 kHz PCM16 passage generated by OpenAI
GPTLive (`gpt-live-1`, voice `marin`). It discusses audio buffering and counts objects.
Only source leading/trailing silence was trimmed, retaining 20 ms of padding on either side.
Internal pauses remain. Output tracks retain all startup, underrun and recovery delay.

`source.json` records the requested passage, returned transcript and timestamps, observed
chunk lengths/arrival times, model, voice and source SHA-256. No customer audio or API
credentials are included. Audio is stored outside Git. Hermetic regression tests generate deterministic PCM in memory.
The metadata records the previous listening run; a fresh GPTLive capture need not match its hash.

## Generate the comparisons

From the repository root, with Cargo, FFmpeg and a C++20 compiler available:

```sh
python3 rust/crates/lk-agents-media/tools/compare_playout.py \
  --input /path/to/gptlive-speech.wav \
  --webrtc /path/to/mac-arm64-release \
  --output /tmp/playout-comparison
open /tmp/playout-comparison/index.html
```

`--webrtc` is an extracted distribution from the `webrtc-a545de4` release of
https://github.com/livekit/rust-sdks/releases/tag/webrtc-a545de4. The helper never downloads
anything or substitutes a mock for NetEq. It records the linked archive's SHA-256 in
`report.json`; callers using another build must review that provenance. The standalone
reference helper currently supports the macOS distribution and system-libc++ Linux builds.
It is not a product dependency.

The Rust example uses the production `playout::Playout`. All four branches receive the
same source samples and actual ordered arrival schedule. NetEq's L16 codec supports
8/16/32/48 kHz, so only that branch is resampled offline 24→48→24 kHz. Each transport chunk
is divided into <=20 ms L16 packets **with the exact same arrival time**. The comparison
is a behavioral/audio reference, not a claim of sample equality, equal achieved delay,
or equivalence to Opus decoder PLC. NetEq can keep concealing after source EOF; its total
concealment counter therefore includes the two-second trailing observation window.

The player includes original speech, untreated playback (no jitter buffer, abrupt silence
on starvation), a plain 100 ms FIFO buffer, actual libwebrtc NetEq, and the Rust controller. Each has its actual delay;
the Playback menu switches tracks at the same wall-clock position. The stereo WAVs provide wall-clock-aligned
baseline/NetEq on the left and candidate on the right. Use headphones or select one channel
in an audio editor. `timeline.csv` and `statistics.txt` describe the candidate's decisions.

Scenarios: clean 100 ms batching, 20 ms lateness, repeated 40 ms stalls, ordered backlog
bursts, a permanent delivery delay increase, a one-second outage, changing 20–200 ms chunk
sizes, and 1000 ppm clock drift. Add `--scenario late_20ms` to render one case, and
`--delay-ms 0` to expose concealment without a startup reserve. The default 20 ms reserve
can absorb the isolated 20 ms delay without concealment. Sweep delay budgets explicitly;
these fixture defaults are not production recommendations.

## Regressions and local performance

```sh
cd rust
cargo test -p lk-agents-media
cargo clippy -p lk-agents-media --all-targets -- -D warnings
cargo run --release -p lk-agents-media --example playout_bench
```

Tests cover atomic overflow/time errors, variable chunk boundaries, a 20 ms underrun,
short-gap recovery, fading long gaps, EOF, cancellation/reset, startup reserve, deterministic
replay, bounded queues, sample accounting and zero allocations in the hot path.
The benchmark reports normal, stalled and backlogged processing times without asserting
hardware-specific speed thresholds. It is not an end-to-end deployment benchmark.

The controller accepts continuous ordered mono 24 kHz PCM16, not discontinuous speech-only
streams. Adapters must normalize format and explicitly finish/reset at lifecycle boundaries.
All source audio is retained unless the caller resets; latency can exceed the adaptive target
following long outages. The short periodic continuation is bounded and confidence-gated;
it is not a port of NetEq DSP and still needs human listening evaluation. Live session
wiring, host exports and transcript source-to-device mapping are outside this crate change.

## Artifacts

Keep source captures and rendered WAV/MP4 files outside the repository. Share listening
examples as GitHub PR attachments or CI artifacts, never committed binary fixtures.
The comparison helper takes an explicit `--input` and writes everything to `--output`.

## Audible fault placement

The renderer measures 10 ms source RMS windows and refuses fixtures without a verified
active fault region. The primary fault starts where the first 50 ms exceeds 150 PCM RMS
and at least 70% of the next second is active. Repeated stalls are restricted to active
source windows. `report.json` records the selected onset, threshold and all window RMS
values. Run `python3 -m unittest discover -s rust/crates/lk-agents-media/tools -p
'test_compare_playout.py'` from the repository root for placement regressions. These
energy checks establish audibility, not semantic intelligibility or a perceptual score.
