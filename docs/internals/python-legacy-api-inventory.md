# Python deprecated and legacy API removal inventory

Add **43 removal groups** to the Python cleanup plan: **11 framework groups and 32 provider
groups**. They include explicitly deprecated arguments/types, ignored configuration, obsolete
aliases and dependency extras. A group can contain multiple symbols or several entrypoints;
43 is not an individual-symbol count. Five further retirement groups require a protocol,
data or lifecycle decision first. Seven groups explain active APIs that should remain.

This inventory accompanies the [final 63-file layout](python-file-layout-inventory.md).
The layout reduces handwritten framework files from 113 to 63 while retaining familiar
public namespaces. API removals are a separate dimension: deleting an argument or alias
usually removes no file. Removing the OpenAI hosted-realtime alias facade saves one plugin
file outside the framework count; conditional transport/data removals are not counted.

Scope is the current handwritten framework, provider plugin Python code and package extras.
Authoritative ABI/Rust declarations and runtime consumers are included where they determine
a Python contract or compatibility boundary. Generated output/stubs are evidence only;
change their source declarations and regenerate when needed. Historical v1 files absent
from this working tree are not counted as pending removals. Snapshot: November 1, 2026.

## Removal rules

Preserve root application imports and useful v1 namespaces, including llm, llm.realtime,
llm.duplex, stt, tts, inference, metrics and types. Their age and normal
re-exports do not make them deprecated. The explicit utils cleanup can migrate redundant
helper spellings and leaf paths, while preserving effective behavior and class names.

An accepted parameter that does nothing is misleading configuration. Remove it, migrate
callers and let the explicit signature reject it; do not retain **kwargs merely to swallow
it. An explicitly deprecated alias should use its existing replacement before deletion.
A setting with real provider behavior still requires migration even if deprecated.

Wire interoperability, saved data and lifecycle contracts need their stated retirement
prerequisites. Do not delete every “legacy” match, rename provider JSON fields globally,
remove working dependency injection from unrelated providers, or combine this cleanup with
the deferred delegation PR. Explicit kept/gated entries below are part of the audit.
