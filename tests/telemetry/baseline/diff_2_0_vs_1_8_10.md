# Agents 2.0 telemetry vs livekit-agents 1.8.10

`schema_2_0.json` (run `SR_aXYDgi5oNPiu`, 3 of 3 scenarios passed, project nativesdk,
2026-11-03) against `schema_1_8_10.json` (run `SR_wRcvH65q684R`). The raw diff, from
`diff.py`, is at the end. Every difference is one of:

- **(a) deliberate**: documented in `docs/internals/telemetry.md`,
  `docs/internals/telemetry-reference.md` or `TELEMETRY_QUESTIONS.md`;
- **(b) parity bug**: fixed (listed with its fix) or still open;
- **(c) scenario variance**: the code path exists and is tested, and this run did not reach it.

## (a) Deliberate

| Difference | Where documented |
| --- | --- |
| `lk.job_id`, `lk.room_id`, `lk.pii.room_name`, `lk.redaction.enabled` on every span, log record and measurement; `job_id`/`room_id`/`lk.agent_name` on every resource | identity stamp, telemetry.md "Destinations" |

## (b) Parity bugs fixed in this pass

| Difference in the first capture | Cause | Fix and test |
| --- | --- | --- |
| No session in a real room: readiness check failed (`RuntimeError: no running event loop` sending `lk.agent.session` messages) | codegen took a writer a host call returned (`Box<dyn ..>`) with `capture_context` on the Tokio thread | `lk-agents-codegen` `returned_value`/`holds_proxy`: an owned returned proxy is taken in its call's context (`owned_in_context`); tests `decl_tests::proxy_calls_consumes_and_lends_by_declaration`, `py_adapters::proxies::a_returned_writer_runs_in_its_calls_context` |
| Agent silent and deaf once a participant publishes a microphone (no user turns, greeting cut after 30 ms, nothing committed) | `_core_open_audio_stream`/`_core_open_video_stream` (host `call`) ran `rtc.AudioStream.from_track` on the core's thread, binding the SDK stream to no running loop | `voice/room_io.py`: the SDK stream opens on the first read, on the loop; `tests/test_room_audio_adapter.py::test_sdk_stream_opens_on_the_loop_not_on_the_cores_thread` |
| `function_tool` span and `gen_ai.execute_tool.duration` missing | the voice tool body's span was opened on `tracer.root()`: no job (never exported to Cloud) and no conversation | `runtime/voice/generation/tools.rs` uses the session's `Cx`; DST rule `spans_nest_and_end` checks that work under a turn carries its job and conversation (counterexample `turn_work_without_identity`) |
| `lk.simulation.job_id` missing everywhere | the job id was read from `simulationJobId`; `SimulationDispatch` names it `job_id` | `worker/ipc/job_trace.rs`; test `the_simulation_identity_is_read_from_the_dispatch` |
| `agent_session` without `lk.dispatch_id`, `lk.job.worker_id`, `lk.job.agent_id` | the voice core declared them and always wrote `None` | `SessionOwner.start(job=SessionJobInfo(...))` carries them from `JobContext`; voice test `the_session_carries_its_jobs_ids` |
| `agent_turn` without `lk.playout.position` when interrupted | the position came only from a sink's physical playout receipt, absent on a cut | the turn accumulator keeps the cut segment's heard position and `StepSpoken` carries it (`cut_at`); DST rule `spans_nest_and_end` (counterexample `cut_while_heard_without_position`) |
| `function_tool` without `gen_ai.tool.description` | voice and text runs passed `None` | the tool's spec description is passed; `agent_run_tests` asserts it |
| `tts_request_run` `lk.provider_request_ids` as an empty array | `AttemptEnd` always wrote the list | `AttemptEnd::new` omits an empty list; `telemetry_tests::a_tts_fallback_adapter_records_each_instance_under_its_attempt` |

## (b) Parity bug still open

| Difference | Cause | Proposed fix (needs a design decision) |
| --- | --- | --- |
| `lk.agents.connection.acquire_time` missing | 2.0's inference STT/TTS never report a connection's acquisition: `TtsMetrics.acquire_time` is always `None` (`lk-agents-core` `TtsMetricState::finish`), the TTS pool records `connected(.., None)`, and STT has no equivalent; only realtime models report it | carry the acquisition on the first `SynthesizedAudio`/speech event of a connection (or a `connected(acquire_time, reused)` on the metric folds), fill it in the inference TTS pool and STT connect; this adds public fields, so not done without approval |

## (c) Scenario variance (verified)

| Difference | Why it is variance |
| --- | --- |
| `event_loop_blocked` span, `agent_session` event `event_loop_blocked` and `lk.blocking.*`, `lk.agents.event_loop.blocked_duration` | recorded only for a stall of 100 ms or more (`telemetry.LoopMonitor`); none happened in 2.0's run. Covered by `voice_telemetry_tests::event_loop_stalls_are_rate_limited` and `a_stall_reaches_the_sessions_of_its_job` |
| `eou_wait` event `user_resumed`, `user_turn` `lk.eou.resume_count` | only when the caller resumes during the end-of-turn wait; present in the previous 2.0 capture (`SR_fnVfRo9NcuUW`) with the same code |
